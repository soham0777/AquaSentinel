# Analytics · detection engine and plume model

| File | What it does |
|---|---|
| [`detector.py`](detector.py) | Python reference of the firmware decision step: CPCB Class C hard limits + robust z-scores against diurnal baselines |
| [`evaluate.py`](evaluate.py) | replays the detector over the dataset and plots the result (`plot_detector_evaluation.png`) |
| [`train_proxy_anomaly_engine.py`](train_proxy_anomaly_engine.py) | fits the proxy weights and exports them as a C header for the firmware |
| [`advection_dispersion_model.py`](advection_dispersion_model.py) | 1-D advection–dispersion estimate of how a plume reaches downstream intakes |
| [`dataset/`](dataset) | 30 days of 15-minute **synthetic** river data with four injected pollution events |

```bash
python evaluate.py
```

On the synthetic dataset the detector flags **all four injected events, each within 30 minutes** (the second reading,
because it acts on 2 of the last 3).

> **Synthetic data, not field data.** The dataset is generated by [`dataset/generate_water_quality_timeseries.py`](dataset/generate_water_quality_timeseries.py)
> to exercise the logic before a permitted river deployment. See [`dataset/README.md`](dataset/README.md).
