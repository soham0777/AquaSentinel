# Analytics · detection engine and plume model

| File | What it does |
|---|---|
| [`detector.py`](detector.py) | Python reference of the firmware decision step: hard limits (pH and DO from CPCB Class C, EC from Class E) + robust z-scores against diurnal baselines; one sample per event |
| [`evaluate.py`](evaluate.py) | replays the detector over the dataset, scores each labelled event (latency, samples, alarms outside events) and plots the result (`plot_detector_evaluation.png`) |
| [`train_proxy_anomaly_engine.py`](train_proxy_anomaly_engine.py) | fits an experimental multivariate (Mahalanobis) model and exports it as a C header; the firmware does not use it |
| [`advection_dispersion_model.py`](advection_dispersion_model.py) | 1-D advection–dispersion estimate of how a plume reaches downstream intakes |
| [`dataset/`](dataset) | 30 days of 15-minute **synthetic** river data with four injected pollution events |

```bash
python evaluate.py
```

On the synthetic dataset the detector flags **all four injected events, each within 30 minutes of the event's start, with
one sample each and no alarms outside the events**. The injected events are tens to hundreds of times larger than the noise,
so this shows the logic works, not how sensitive it is; the real false-alarm rate needs pilot data with lab samples.

> **Synthetic data, not field data.** The dataset is generated by [`dataset/generate_water_quality_timeseries.py`](dataset/generate_water_quality_timeseries.py)
> to exercise the logic before a permitted river deployment. See [`dataset/README.md`](dataset/README.md).
